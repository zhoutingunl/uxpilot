# 报告视频的输入与返回音轨

DuckKing 适配器在 `browser.video: true`、`browser.record_audio: true`（默认）时记录音轨。已有 `task.audio` 语音用例的授权麦克风输入与网页真正连接到 AudioContext 播放端的输出一起进入 `session.mp4` 和 `review.mp4`。网页音效、本地语音和云端回复均按实际 Web Audio 播放图录制；不会把收到但未播放的 `response.pcm` 直接当作播放声音。

麦克风只在配置了音频夹具、且执行 `speak` 的按住窗口内记录，不会额外请求麦克风。通用自动规划任务没有音频夹具时，不能声称测试过语音输入。中文文件样本、已有英法文件样本和 MiniMax TTS 生成的麦克风输入使用同一采集路径。

## 文件与回看

- `session.mp4`：完整录像及 AAC 音轨。
- `review.mp4`：供人工查看的精简录像，音画一起剪切，保留有声音的完整时段。
- `judge.mp4`：同画面、同时间线的无声副本，供现有视觉模型评审；音轨不发送给视觉模型。独立语音 ASR 仍是单独的配置服务。
- `audio-capture.json`：实际捕获的输入/输出流、信号区间、采样率、时钟估计及缺失告警。
- `audio-capture/track-*.wav`：原始数字采集流，以本轮任务开始为时间零点；保留未发声区间。麦克风夹具、返回协议 PCM、实际播放流是不同证据。
- `video-timeline.json`：精简版与完整录像的时间映射。

报告视频默认不静音，点击播放即可听到已捕获的声音。没有有效音频或采集失败时明确标注，不用字幕、模拟回答或重新合成声音补成“实际播放”。历史无声录像没有足够的播放时间证据，保持原样，需要重新运行语音用例生成带声音的报告。

## 同步与范围

当前支持 Chromium 的主页面 Web Audio 图。采集节点是旁路，不改变应用播放连接或主动恢复被挂起的 AudioContext；定向断开播放连接时会同步断开录音旁路，避免录到已被打断的后续内容。输入仅使用授权 getUserMedia 流，并依据按住窗口裁切；页面只收到原有麦克风流。

采集采用同步创建的 ScriptProcessor，以免异步安装处理器漏掉首段声音。Chromium 输入缓冲与播放时间的偏移通过生成音调回归检查校准；输出采用 [AudioContext.getOutputTimestamp](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/getOutputTimestamp) 映射到页面时钟，麦克风使用 AudioContext 渲染时钟。原始时钟、处理缓冲估计记录在音频元数据中。视频仍为 2 fps，不能作为逐帧口型或硬件延迟的高精度测量。

采集对象是浏览器数字音频，不是设备扬声器实录；系统音量、外部蓝牙设备和真实房间声学不在录制范围内。未进入 Web Audio 的 HTML 媒体或 speechSynthesis 不在当前支持范围，不能用这里的静音结果判断它们没有声音。输入/输出混音有防削波限制，不用于声压级比较。

每轮最多 8 路采集流、默认 256 MB 原始音频上限（`browser.audio_max_bytes`），时长受录像上限约束。过载、超限、缺失及编码错误会保留状态。音频与麦克风夹具属于运行证据，不提交到 Git。

## 验证

离线测试使用真实 Chrome、生成的 440 Hz 输入与 880 Hz 页面输出，分别验证来源频率、输入窗口、输出时间对齐、断开后停止录制、WAV 长度和采集边界。另用中段音调验证精简时不会剪掉语音，`session.mp4` / `review.mp4` 有音轨而 `judge.mp4` 没有音轨。离线测试不调用语音云服务、不访问公共演示站。
